# ギタークラブ会計アプリ

大阪大学ギタークラブの会計業務を効率化するために開発した、Ruby on Rails製のWebアプリケーションです。
自身が会計係を務める中で感じた業務上の課題を、実際の業務フローを分析した上で開発しました。

## 背景・課題

部員約40名、会計担当は実質1名という体制の中、以下のような課題がありました。

- レシートの保存、Excelへの記帳、送金、完了確認という工程が多く、特に「立替金を返済した後の完了記録」や「レシート写真の保管」など、記録すること自体を忘れてしまう場面があった
- 会計以外にも部長やイベント係など、支出の意思決定に関わる人がいるが、収支は会計担当がLINEに手動で共有しない限り確認できない構造になっており、共有側(会計)にも都度の残高計算・報告という追加の手間が発生していた
- 過去の会計データはExcel・紙の記録に分散しており、現時点では参照コストは大きくないものの、年数を重ねるほど散在したデータの参照が煩雑になっていくことが見込まれた


## 設計で重視したこと

機能を単純に増やすのではなく、**本当に必要な機能に絞り込むこと**を意識しました。

- 部員数や支出は年によって変動が大きく、精緻な予算計画は実態と乖離しやすいと判断し、予算管理機能ではなく実績の記録・可視化に注力した。会計残高は表示しつつ、支出判断の妥当性は金額そのものより「何にいくら使ったか」という内容の透明性で担保する設計とした
- カテゴリ機能、欲しいものリスト、ユーザー個別アカウント管理などは実装や検討を行ったが、費用対効果や利用率の不確実性、権限設計コストを踏まえて見送り・撤去し、必要最小限の構成を維持した
- 利用者側の負担を増やさないことを一貫して意識し、閲覧用パスコードを部室の鍵番号と揃えて学習コストを下げたり、Excel運用で培われていた一覧性をエクスポート機能で補うなど、既存の使い勝手を損なわない工夫を取り入れた

## 主な機能

| 機能 | 内容 |
|---|---|
| 残高自動計算 | 取引データから総残高・口座残高・現金残高を自動集計 |
| 年度切り替え | 4月始まりの会計年度でデータを絞り込んで表示 |
| 取引の登録・編集・削除 | 日付・金額・支払方法・レシート写真などを記録 |
| 未精算一覧 | 立替払いでまだ処理されていない取引を抽出し、チェック操作で処理完了にできる |
| Excelエクスポート | 記録した取引データをExcel形式で出力し、決算・引き継ぎに活用 |
| ロール別ログイン | 会計担当と閲覧者(部員)でアクセスできる操作を分離した簡易ログイン |

## 技術スタック

- Ruby on Rails 6.1
- SQLite3
- Bootstrap 4
- Active Storage(レシート画像の添付)
- caxlsx(Excel出力)

## 開発の進め方

既存のCRUDアプリケーションの構造を土台に、認証をロールベースのシンプルな仕組みに置き換え、取引管理に特化したモデル・機能を追加する形で開発しました。
機能の要否は、実際の会計業務のヒアリングと自己の経験に基づいて都度検討し、見送った機能についても理由を明確にした上で判断しています。
